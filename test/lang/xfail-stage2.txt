# The expected failures of the self-hosted compiler (stage2), passed to
# run_tests.py as --xfail; test/lang/xfail.txt stays the list for stage1.
# Entries are path prefixes relative to test/lang, so a directory covers
# everything under it, and an entry leaves this list in the commit that makes
# its tests pass (D14.4).
#
# Phase B builds stage2 one module at a time. With the lexer, the parser, the
# module loader and the driver ported (T-031 to T-034), stage2 reads the entry
# file, walks the import closure and reports the lexical, syntax and import
# errors of D14.2 with stage1's words and stage1's exit statuses, so the
# `fail` tests whose diagnostics come from those three passes now pass and
# have left this list: the whole of fail/lexical, the loader's own tests under
# fail/modules, and the parse-error tests scattered through the other areas.
#
# What is left is what needs a pass stage2 does not carry yet. Every `fail`
# entry below is a test whose diagnostic is the checker's (T-035 and after),
# which stage2 answers with `internal error: this compiler cannot check or
# build a program yet` and exit 2; `run` and `programs` need the checker and
# the emitter both, so they shrink last and stay whole directories until then.
# The two entries under fail/operators are the harness running without
# --no-unsupported semantics for stage2: they use floats and `?:`, which the
# transliterated parser refuses exactly as the bootstrap does.
