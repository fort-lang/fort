# The expected failures of the self-hosted compiler (stage2), passed to
# run_tests.py as --xfail; test/lang/xfail.txt stays the list for stage1.
# Entries are path prefixes relative to test/lang, so a directory covers
# everything under it, and an entry leaves this list in the commit that makes
# its tests pass (D14.4).
#
# Phase B builds stage2 one module at a time. With the lexer, the parser, the
# module loader, the driver and the whole checker ported (T-031 to T-036),
# stage2 reads the entry file, walks the import closure, resolves every
# top-level declaration, checks every function body and reports the lexical,
# syntax, import and program errors of D14.2 with stage1's words, stage1's
# positions and stage1's exit statuses. Every `fail` test therefore passes,
# and the list below holds none of them but the two named at its end: T-036
# took out the remaining 111 entries, the whole of fail/arrays, fail/builtins,
# fail/casts, fail/pointers, fail/spans, fail/stdlib and fail/strings among
# them, every one of which needed a diagnostic reported while checking a
# statement.
#
# What is left is what needs a pass stage2 does not carry yet. `run` and
# `programs` need the emitter, which is not ported: stage2 checks those
# programs and then answers `internal error: this compiler cannot build a
# program yet` with exit 2, so they stay whole directories until it lands.
# The two entries under fail/operators are the harness running without
# --no-unsupported semantics for stage2: they use floats and `?:`, which the
# transliterated parser refuses exactly as the bootstrap does.
