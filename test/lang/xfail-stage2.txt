# The expected failures of the self-hosted compiler (stage2), passed to
# run_tests.py as --xfail; test/lang/xfail.txt stays the list for stage1.
# Entries are path prefixes relative to test/lang, so a directory covers
# everything under it, and an entry leaves this list in the commit that makes
# its tests pass (D14.4).
#
# Phase B builds stage2 one module at a time. With the lexer, the parser, the
# module loader, the driver and the checker's declarations and expressions
# ported (T-031 to T-035), stage2 reads the entry file, walks the import
# closure, resolves every top-level declaration and reports the lexical,
# syntax, import and declaration errors of D14.2 with stage1's words and
# stage1's exit statuses. The `fail` tests whose diagnostics come from those
# passes now pass and have left this list: the whole of fail/lexical, the
# loader's own tests under fail/modules, the parse-error tests scattered
# through the other areas, and, with T-035, the twenty tests whose diagnostic
# is reported while a module-level declaration is resolved -- extern
# signatures, runtime signatures, `main`, module-level initializers and
# constant cycles, struct layout and infinite size, enum values, field
# markers.
#
# What is left is what needs a pass stage2 does not carry yet. Every `fail`
# entry below is a test whose diagnostic the checker reports while checking a
# function body, which is src/bootstrap/check_stmt.c and has not been ported
# (T-036): src/fort/check.ft resolves the declarations of a module and stops
# before the bodies, since the one call that closes the cycle between the two
# C files cannot cross two fort modules (D9.5). stage2 therefore reports
# nothing for those files and answers `internal error: this compiler cannot
# build a program yet` with exit 2. `run` and `programs` need the checker and
# the emitter both, so they shrink last and stay whole directories until then.
# The two entries under fail/operators are the harness running without
# --no-unsupported semantics for stage2: they use floats and `?:`, which the
# transliterated parser refuses exactly as the bootstrap does.
