# The program list of tools/sweep_untyped.sh. Read that script's header for the
# six classes a row may expect, the two a row may not, the two command lines
# and the frame each body goes into.
#
# The list declares its own length below, and the script holds it as an
# equality, so a deleted row fails the run instead of passing in silence. A
# ticket that adds or removes a row moves that number with it.
#
# What the sweep covers.
#
# Section A reproduces T-128's sweep: the four routes of check_operands, one
# program per branch and per operand order, both ends of [2^63, 2^64 - 1], the
# char clause, the float clause, null, bool, a string, a typed operand, a
# compound assignment and a `?:`.
#
# Section B widens it past the untyped-pair shapes, along the list D4.1 gives:
# every context an untyped constant takes its type from, each one with an
# untyped expression that folded to no value beside it. The columns of the
# widening are the context (a declaration, an assignment, a compound
# assignment, an argument, a return, a `case` operand, an index, a span bound,
# a `new` count, a binary operand), the clause of D4.5 that answers with no
# context (integer, char, float), the two expressions that fold to no value (a
# shift with a variable count and a `?:` with a run-time condition), and the
# operand order.
#
# Section C widens it along D6.2 instead: every operator family, with an
# untyped operand that folded to no value on each side.
#
# What the sweep cannot reach.
#
# It builds one function and one frame, so it says nothing about a module
# boundary, a generic, a struct field, ownership or a loop. It holds the
# expression layer, which is where the defect of T-127 and T-128 lived, and it
# holds it for the shapes below and for no others. The measurement that speaks
# for the whole repository is a different one and it is tools/diff_ir.sh, which
# reads every module of every program the repository holds with
# `opt -passes=verify`.
#
!rows 163
